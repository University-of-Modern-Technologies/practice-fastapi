# Архітектурні рішення (ADR)

Тут записано, **чому** система влаштована саме так. Як вона влаштована — в
[`ARCHITECTURE.md`](../../ARCHITECTURE.md), як із нею працювати — у
[`README.md`](../../README.md) і [`docs/development.md`](../development.md).

Кожен запис — одне рішення у форматі Майкла Найгарда (Michael Nygard):

- **Статус** — `прийнято`, `замінено` (з посиланням на новий запис) або
  `скасовано`.
- **Контекст** — яка задача стояла й які сили тиснули на рішення.
- **Рішення** — що саме вирішено, з посиланнями на код.
- **Наслідки** — що стало простіше, що складніше і яких правил тепер треба
  дотримуватися в новому коді.

## Як додати запис

1. Візьми наступний вільний номер і назви файл `NNNN-<коротко-англійською>.md`.
2. Заповни чотири розділи. Пів сторінки — нормальний обсяг; якщо виходить
   більше трьох, найімовірніше, це кілька рішень.
3. Додай рядок у таблицю вище й надішли запис тим самим pull request, що й
   зміну, яку він пояснює.
4. Ухвалене рішення не переписують. Якщо воно змінилося, пишуть новий запис, а
   в старому міняють статус на «замінено» й ставлять посилання на новий.
