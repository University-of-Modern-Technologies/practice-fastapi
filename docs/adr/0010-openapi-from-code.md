# 0010. Опис API виводиться з коду, відмови оголошуються руками

**Статус:** прийнято

## Контекст

Опис API (OpenAPI, Swagger UI на `/api/docs`) читають ті, хто пише клієнт, і ті,
хто вперше заходить у код. Опис, який пишуть окремо від коду, старіє з першої ж
правки: поле додали в схему, а в описі його немає, маршрут перейменували, а опис
показує старий шлях. Розбіжність ніхто не помічає, бо опис нічого не виконує.

Водночас не все можна вивести автоматично. Схему запиту й тіло успішної відповіді
код знає. А от чим операція може відмовити — застарілою версією, відсутнім
записом, станом, що забороняє дію, — знає лише сервіс під обробником, і ці
відмови існують тільки як винятки, кинуті десь глибше.

## Рішення

- **Операції, параметри й поля бере FastAPI** із сигнатур маршрутів і моделей
  pydantic, тих самих, що перевіряють запит і серіалізують відповідь.
- **Документ доводиться до справжнього контракту** в
  `_install_openapi` (`backend/app/factory.py`): `400` і `500` додаються до
  операцій за правилом, а згенерована фреймворком `422` прибирається, бо помилку
  валідації цей API повертає як `400`. Імена операцій виводяться з методу й
  шляху (`operation_id` у `backend/app/core/openapi.py`).
- **Відмови оголошуються руками поруч із маршрутом:**
  `responses=refusals(401, 403, 404, 409)` (`backend/app/core/openapi.py`).
  Тіло будь-якої відмови — спільний конверт помилки `ErrorResponse`.
- **Опис лежить у репозиторії** — `backend/openapi.json`. Після зміни API його
  перегенеровують з теки `backend` командою
  `uv run python -m scripts.export_openapi` і комітять разом зі зміною. Скрипт
  будує документ тією самою фабрикою, що й сервер, без підключення до сховищ і
  без `.env`, тож на кожній машині виходять ті самі байти.
- **Тести тримають опис чесним** і входять у звичайний `pytest`, а отже в
  `check:api` і CI:
  - `backend/tests/unit/test_openapi_document.py` — закомічений файл збігається
    з тим, що будує код; кожен змонтований маршрут описаний або свідомо лишений
    поза описом, а кожна описана операція справді обслуговується;
  - `backend/tests/unit/test_openapi_refusals.py` — механічні правила для
    відмов: операція з `version` оголошує `409`, захищена операція — `401`.

## Наслідки

- Операції, параметри й поля в описі не можуть розійтися з кодом: вони
  беруться звідти ж, а дрейф закоміченого файла ламає CI.
- Відмови можуть відставати. Нова гілка логіки, що кидає `404` чи `409`, сама в
  опис не потрапляє, і тести ловлять лише ті пропуски, що мають механічну
  ознаку. Решту перевіряє людина на review: змінилася логіка відмов — має
  змінитися і `refusals(...)` поруч із маршрутом.
- Зміна API видна в дифі pull request як зміна `openapi.json`, тож рев'ювер
  бачить наслідок для клієнта, не читаючи сервіс.
- `/api/docs` і `/api/openapi.json` вимкнені в production
  (`API_DOCS_ENABLED`, типово `false` при `APP_ENV=production`); на машині
  розробника й у тестах вони є.
